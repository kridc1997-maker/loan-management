--- SERVICES (business logic) ---

backend/src/services/loanService.ts
  คืออะไร : logic หลักการสร้างสัญญาและรับชำระ

  ฟังก์ชันสำคัญ:
    createLoan()       — สร้างสัญญา + คำนวณงวด + หักเงินสด
    receivePayment()   — บันทึกชำระ + แบ่ง interest/principal

  *** จุดสำคัญ ***
  การแบ่ง interest_paid / principal_paid:
    - paymentType = 'rollover'    → ทั้งหมดเป็น interest
    - paymentType = 'full'        → ปิดสัญญา ดอก+ต้นที่เหลือ
    - มี installmentId            → ใช้ interest_portion จากงวดนั้น (แม่นยำ)
    - ไม่มี installmentId         → interest first แล้วค่อยต้น

  แก้เมื่อ : เปลี่ยนวิธีคำนวณดอก, เพิ่ม payment type ใหม่

backend/src/services/authService.ts
  คืออะไร : login, bcrypt verify password, สร้าง JWT token
  แก้เมื่อ : เปลี่ยน JWT expiry, เพิ่ม refresh token

--- REPOSITORIES (query database) ---

backend/src/repositories/dashboardRepository.ts
  คืออะไร : query ทุก KPI ในหน้า Dashboard

  field ที่ return:
    cashOnHand        — ยอดเงินสดจาก cash_transactions ล่าสุด
    outstandingPrincipal — ต้นคงค้างทุกสัญญา active+overdue
    profitToday       — SUM(interest_paid) วันนี้ เฉพาะ non-daily
    profitThisMonth   — SUM(interest_paid) เดือนนี้ เฉพาะ non-daily
    receivedToday     — SUM(principal+interest) รับมาทุก type วันนี้
    collectionRate    — งวดที่จ่ายแล้ว/งวดทั้งหมด 30 วัน
    badDebtAmount     — หนี้เสียที่ยังไม่กู้คืน

  แก้เมื่อ : เพิ่ม KPI card ใหม่ใน Dashboard

backend/src/repositories/loanRepository.ts

backend/src/repositories/paymentRepository.ts

================================================================================
  DATABASE SCHEMA สรุป
================================================================================

ตาราง            คีย์หลัก   เก็บอะไร
--------         -------    --------
users            id         ผู้ใช้ระบบ (admin/staff)
customers        id         ลูกค้าที่กู้เงิน
loans            id         สัญญากู้ยืม
loan_installments id        ตารางงวดชำระของแต่ละสัญญา
payments         id         ประวัติรับชำระทุกครั้ง
cash_transactions id        ประวัติเงินสดเข้า-ออก
bad_debts        id         สัญญาที่โอนเป็นหนี้เสีย
monthly_snapshots id        snapshot รายเดือน (ยังไม่ได้ใช้งาน)
settings         key        ค่าตั้งต้นระบบ (key-value)
audit_logs       id         log การกระทำสำคัญ

--------------------------------------------------------------------------------
  ความสัมพันธ์:
  customers → loans (1 คน มีได้หลายสัญญา)
  loans → loan_installments (1 สัญญา มีหลายงวด)
  loans → payments (1 สัญญา มีหลาย payment)
  loan_installments → payments (งวดนึง ผูกกับ payment ได้)
  loans → bad_debts (สัญญาที่เป็นหนี้เสีย)

================================================================================
  WORKFLOW: เมื่ออยากเพิ่ม FEATURE ใหม่
================================================================================

  1. เพิ่ม column ในฐานข้อมูล?
     → สร้างไฟล์ migration ใหม่ใน backend/src/db/migrations/
     → ชื่อไฟล์ต้องเรียงลำดับ: 006_xxx.ts
     → Push → Render จะรัน migration ให้อัตโนมัติ

  2. เพิ่ม API endpoint ใหม่?
     → แก้ backend/src/routes/index.ts เพิ่ม route
     → ถ้า logic ซับซ้อน → แยกไปใส่ใน service/repository
     → เพิ่ม function ใน frontend/src/api/endpoints.ts

  3. เพิ่ม field ใน response?
     → แก้ backend query (repository หรือ routes)
     → เพิ่ม field ใน frontend/src/types/index.ts
     → เพิ่มใน mockData.ts ถ้า interface นั้นมี mock
     → ใช้งานในหน้าที่ต้องการ

  4. เพิ่มหน้าใหม่?
     → สร้างไฟล์ใน frontend/src/pages/
     → เพิ่ม route ใน frontend/src/App.tsx
     → เพิ่มเมนูใน frontend/src/components/layout/Sidebar.tsx

================================================================================
  DEPLOY PROCESS
================================================================================

  1. แก้โค้ด
  2. git add . && git commit -m "อธิบายการเปลี่ยนแปลง"
  3. git push origin main
  4. Render จะ build อัตโนมัติ (~3-5 นาที)
     - cd frontend && npm install --include=dev && npm run build
     - cd backend && npm install --include=dev && npm run build
     - npm run migrate:prod (รัน migration ที่ยังไม่ได้รัน)
     - node dist/app.js

  ดู log ที่: render.com → loan-management → Logs
  Database:   supabase.com → SQL Editor

================================================================================
  COMMON FIXES — ปัญหาที่เคยเจอ
================================================================================

  ปัญหา: build failed "Property X does not exist on type Y"
  สาเหตุ: เพิ่ม field ใน backend แต่ลืมเพิ่มใน frontend/src/types/index.ts
  แก้: เพิ่ม field ใน types/index.ts และ mockData.ts

  ปัญหา: migration failed ".ts file not found"
  สาเหตุ: knex_migrations เก็บชื่อไฟล์ .ts แต่ compiled เป็น .js
  แก้: UPDATE knex_migrations SET name = REPLACE(name, '.ts', '.js')

  ปัญหา: login 500 error
  สาเหตุ: table ไม่มี หรือ column type ผิด
  แก้: ตรวจสอบ Supabase Table Editor / Render Logs

  ปัญหา: กำไรวันนี้แสดงผิด (ดอกทั้งหมดขึ้นในงวดแรก)
  สาเหตุ: payment ไม่มี installmentId ทำให้ใช้ "interest first" logic
  แก้: ถ้าชำระผ่าน installment ต้องส่ง installmentId มาด้วยเสมอ
       แล้ว loanService จะใช้ interest_portion จากงวดนั้นแทน

  ปัญหา: เงินสดใน navbar ไม่อัพเดท
  สาเหตุ: ไม่ได้ dispatch 'header-refresh' event หลัง transaction
  แก้: เพิ่ม window.dispatchEvent(new Event('header-refresh'))
       หลัง payment/cashflow สำเร็จ
